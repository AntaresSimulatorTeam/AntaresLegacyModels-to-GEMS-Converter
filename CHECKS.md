# Checks

What this repository checks, when, and where to look. The first two sections are
written by hand; the list of tests is generated from their docstrings.

## When the checks run

| Workflow | When | What it runs |
|---|---|---|
| [`ci.yml`](.github/workflows/ci.yml) → [`run-tests.yml`](.github/workflows/run-tests.yml) | every push, on any branch | type checking (`mypy src/`), formatting (`black --check src/`), the consistency tests (`tests/consistency/`, before the Antares download, to fail fast), then the other tests with the Antares Simulator binary |
| `check-antares-update.yml`, `check-antares-craft-update.yml`, `check-gemspy-update.yml`, `check-views-builder-update.yml` | weekly | on a new release of the dependency, opens an issue and posts the result of `run-tests.yml` run with that release (without mypy and black) |
| [`update-library-checksums.yml`](.github/workflows/update-library-checksums.yml) | push to `release/**` or `hotfix/**` | updates the `.sha256` file of each library that changed |

Run them locally with the commands of the "Running Tests" section of
[AGENTS.md](AGENTS.md).

## Checks the converter runs on its input

These run at each conversion, not only in CI: the conversion stops with a
`ValueError` naming the template or file at fault.

- **Templates, at load** ([`parsing.py`](src/antares_gems_converter/input_converter/src/parsing.py),
  `ConversionTemplate` validators): exactly one template parameter, named `area` or
  `link`; a known cluster type and link attributes; exclusions well formed and able
  to match an object the template iterates over; no placeholder left once
  instantiated. See "Template loop" in [AGENTS.md](AGENTS.md).
- **Templates against the libraries** ([`checks.py`](src/antares_gems_converter/input_converter/src/checks.py),
  `check_converted_models_are_in_libs`): the model of each template exists in the
  given libraries, and each component declares exactly the parameters and properties
  of that model.
- **Libraries** (`parse_library`): each library file parses with GemsPy.

### Consistency of the YAML artifacts and of this documentation (`tests/consistency/`)

The libraries, catalogs, taxonomies and view configs of the package, wherever they are stored: they are found by their root key (see `tests/consistency/yaml_artifacts.py`). No Antares binary is needed: CI runs these tests first, in the "Consistency checks" step, so they fail fast.

#### [`test_catalogs.py`](tests/consistency/test_catalogs.py)

The catalogs agree with the taxonomy they declare, and each flattened taxonomy with its main taxonomy.

| Test | Guarantee |
|---|---|
| `test_metrics_output_ids_and_properties_are_declared` | In each catalog, every metric term references a category of the declared taxonomy and an output id of that category (or of a parent category), and every breakdown key is a property of the category (or of a parent category). |
| `test_metrics_output_ids_and_properties_are_declared_in_flattened_taxonomy` | Same check as `test_metrics_output_ids_and_properties_are_declared`, against the flattened copy of the declared taxonomy (the one given to GEMS-ViewsBuilder). Skipped when the taxonomy has no flattened copy. |
| `test_flattened_taxonomy_matches_main_taxonomy` | Each flattened taxonomy, maintained by hand, has the categories of its main taxonomy, none with a parent, each with the outputs and properties it inherits in the main taxonomy. |

#### [`test_checks_doc.py`](tests/consistency/test_checks_doc.py)

The list of tests in CHECKS.md is complete and up to date.

| Test | Guarantee |
|---|---|
| `test_every_test_has_a_docstring` | Every test module and test of a directory listed in CHECKS.md has a docstring stating what it guarantees. |
| `test_documented_directory_has_a_title` | Every test directory listed in CHECKS.md has a title, in the docstring of its `__init__.py`. |
| `test_checks_doc_is_up_to_date` | CHECKS.md lists the current tests of its directories, with their current docstrings. |

#### [`test_model_taxonomy.py`](tests/consistency/test_model_taxonomy.py)

The models of each library implement the taxonomy categories they declare.

| Test | Guarantee |
|---|---|
| `test_models_implement_taxonomy_contract` | In each library, every model with a taxonomy category references a category of the declared taxonomy and of its flattened copy, and has all the variables, parameters, ports, port-field definitions, constraints, binding constraints, extra outputs and properties of that category (GemsPy `check_library_against_taxonomy`).<br>Limits: a model without a taxonomy category is not checked (e.g. the models of `andromede_v1_models.yml`). |

#### [`test_views_builder.py`](tests/consistency/test_views_builder.py)

GEMS-ViewsBuilder accepts the libraries, catalogs, taxonomies and view configs of the package.

| Test | Guarantee |
|---|---|
| `test_view_configs_are_compatible_with_views_builder` | For each taxonomy, GEMS-ViewsBuilder validates the libraries, catalogs and view configs that declare it, against the flattened copy of the taxonomy if any, with the checks of its `validate_input_data` (simulation tables aside), and every view config gets at least one metric. The view configs are given aggregation patterns, as for a study. |
| `test_view_config_lists_all_metrics_of_its_catalogs` | Each view config lists every metric of the catalogs it uses, in the catalog order, and nothing else, to be trimmed for each study. |

#### [`test_yaml_artifacts.py`](tests/consistency/test_yaml_artifacts.py)

Guards that every YAML artifact of the package is covered by the consistency tests.

| Test | Guarantee |
|---|---|
| `test_yaml_file_is_a_known_artifact` | Every YAML file under `src/antares_gems_converter/` has a single root key among `library`, `catalog`, `taxonomy`, `view` and `template`, so no file escapes the consistency tests. |
| `test_artifact_is_stored_in_the_directory_of_its_kind` | Every YAML artifact is stored under the directory of its kind (`libs/`, `catalogs/`, `taxonomies/`, `views_config/`, `input_converter/data/model_configuration/`, subdirectories allowed); libraries, catalogs, taxonomies and view configs use the `.yml` extension. |
| `test_artifacts_of_each_kind_are_found` | At least one library, catalog, taxonomy and view config is found, so a renamed root key or directory cannot silently empty the tests. |
| `test_artifact_ids_are_unique` | No two libraries, catalogs, view configs or main taxonomies share an id. |
| `test_taxonomy_file_is_valid` | Every taxonomy, flattened copies included, loads with GemsPy `load_taxonomy`. |
| `test_flattened_taxonomy_has_a_main_taxonomy` | Every `<name>_flattened.yml` taxonomy has a `<name>.yml` main taxonomy, with the same id. |
| `test_declared_taxonomy_exists` | Every library, catalog and view config declares a taxonomy that exists. |

Not listed here yet: `tests/antares_historic/`, `tests/antares_runner/`, `tests/input_converter/`. See the Test Architecture section of [AGENTS.md](AGENTS.md).
